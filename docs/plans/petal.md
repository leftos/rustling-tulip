# Petal: the native client's new look

The user approved "Petal" for the native client (`apps/native`): a graphite ground, a tulip-coral accent, Schibsted Grotesk as the UI face beside Geist Mono, status shapes as well as colours, and refined pane headers and chips. The canvas is https://claude.ai/artifact/85m8ZhzEA4ovQhJqhjCn5S (seven boards). Index line: [MAIN.md](./MAIN.md), the Petal wave. This subplan splits the look into brief-sized items that build on today's code, lists what is settled, and asks what the boards leave open.

## Rulings

- **Order (user):** Petal lands before the rest of native Phase 4, so it is MAIN.md's Wave 1, ahead of Waves 2–5. P4.12b / P4.12c (Wave 2, in `spawn_form.rs` / `session_menu.rs`) wait for it; PT.8a and PT.8b restyle the menu and dialog they extend. Waves 2–5 then build their new UI with Petal's tokens directly.
- **Scope:** only what exists today is restyled. The boards' unbuilt features are visual targets for their own waves, not items here:
  - Dashboard board, the tab bar's Terminals / Dashboard switch and its badge, the rail's Needs You view, the asking toast that quotes the command → Wave 7 (Alerts, Dashboard and Needs You), on Wave 6's `pending_input`.
  - Settings → Alerts board → Wave 7 (spoken alerts, SA steps).
  - Conversation board and the pane header's Terminal / Conversation toggle → the backlog idea "Conversation view (GUI mode)", which has no wave yet.
  - Phone dashboard board → Wave 12 (mobile app, MA6 monitor and respond).
  - Subagent rows under a leaf → Wave 8; the `DS` dispatch leaf → Wave 9; the PR / issue chips (`#412`, `#1187 draft`) → the backlog idea "Link a worktree to a GitHub issue or PR".
- **One palette module.** Every UI colour lives in a plain-Rust `apps/native/src/palette.rs`; views name tokens, never literals. `lib.rs` re-exports the names its 27 importing files use today (`TEXT`, `MUTED`, `BORDER`, `PANEL_BG`, `BAR_BG`, `HOVER_BG`, `DANGER`, `WARNING`, …), so recolouring is a change to one file. PT.2 adds every Petal token up front, so later items read `palette.rs` and never edit it.
- **Tokens** (hex from the boards; contrast measured with the WCAG formula `theme.rs` uses):
  - Grounds: `GROUND` #111013 (main area), `SUNKEN` #0B0A0D (rail, footer), `SURFACE` #161519 (sidebar, tab bar, dialogs), `RAISED` #1B1A1F (focused pane header, segmented controls), `CHIP` #232129 (selected row, chips, popovers), `HOVER` #2C2A33, `TERMINAL_GROUND` #0C0B0E.
  - Lines: `LINE` #2A2830, `LINE_STRONG` #3A3742 (outlined buttons, dialog borders).
  - Text: `TEXT` #EDE9E4 (15.69:1 on `GROUND`), `TEXT_2` #A7A2AD (7.28:1 on `SURFACE`), `SUBTLE` #8C8794 (5.2:1 on `SURFACE`, 4.55:1 on `CHIP`), `FAINT` #6E6A77 (idle glyph only; 3.45:1, not for text).
  - Accent: `ACCENT` #F07A62, `ON_ACCENT` #1C100D (6.79:1 on the accent).
  - Status: `WORKING` #6CA6FF, `ASKING` #F6BC4E with `ON_ASKING` #2A1B00 (9.74:1), `WAITING` #4FC89D, `DANGER` #F26D6D; runtime tags claude = `ACCENT`, codex `LILAC` #C9B8FF.
  - Diff: insert wash `WAITING` at 12%, delete wash #E56A6A at 13%, filler white at 2.5%, removed text #E58A8A, added text #7FD3AE.
- **Status shapes** replace the colour-only dot: working = a faint ring with a spinning arc and a filled core (`WORKING`), asking = a diamond with a `?` (`ASKING` / `ON_ASKING`), waiting = a hollow ring (`WAITING`), idle = a small dot (`FAINT`). `Working` → working ring and `AwaitingInput` → asking diamond; which `Idle` sessions get the waiting ring is open question 4. The glyph works on today's `SessionStatus`; Wave 6's hooks make the states more accurate without changing the mapping. PT.4 absorbs Wave 2's "Leaf status dot: pulse while working, hollow while spawning" line, which is deleted when PT.4 lands.
- **Pixel probes read tokens by name.** `tests/smoke_window.rs` already compares against `lib.rs`'s `PANEL_BG` / `BAR_BG`, so it follows the values; PT.5 adds a probe of the coral active-rail bar, since `SUNKEN` (#0B0A0D) is close to the all-black capture the probe guards against.

## Open questions

1. **Schibsted Grotesk: licence and bundling.** It is SIL OFL 1.1 with no Reserved Font Name (upstream `github.com/schibsted/schibsted-grotesk`, release 1.100, also in `google/fonts` `ofl/schibstedgrotesk`), so bundling beside the four OFL mono families is allowed with its `OFL.txt`. The boards use weights 400–700 (800 only for the `!` badge).
   - (a) Recommended: four static TTFs from the repo's `fonts/ttf/` (Regular, Medium, SemiBold, Bold; 490,976 bytes together), the `!` badge drawn at Bold. Worst case: the exe grows by about 0.5 MB, and a future italic needs another file.
   - (b) The variable TTF, one file. Worst case: whether GPUI 0.2.2 on DirectWrite picks weights from a variable font's axes is unmeasured; every weight might render as the default instance.
   - (c) No bundle; the root asks for "Schibsted Grotesk" and falls back to Segoe UI Variable. Worst case: nobody without the font installed sees Petal's type.
2. **Geist Mono's middle weights.** The boards' mono chips use 500 and 600; only 400 and 700 are bundled.
   - (a) Recommended: draw chips at 400 and bold headers at 700. Worst case: chips read a shade lighter than the board.
   - (b) Add Geist Mono Medium and SemiBold (about 300 KB). Worst case: two more faces the terminal font list never uses.
3. **Per-session accent colours.**
   - (a) Recommended: kept where they are today (leaf stripe, focused pane border, header accent line); the default becomes coral and the presets become Petal's: Coral #F07A62, Rose #E7849B, Ochre #D9A15C, Periwinkle #8FB3F0, Sky #8FD3E8, Lilac #C9B8FF. Accents already saved stay as stored hex. Worst case: a session saved with an old saturated accent (Emerald #22c55e) clashes with the muted ground until the user repicks it.
   - (b) The accent shows only on the stripe; every focused pane is bordered in the app's coral. Worst case: side-by-side panes lose their per-session frame colour, and `ui_appearance`'s frame specs change meaning.
   - (c) Drop per-session accents. Worst case: removes a shipped setting and its three levels.
4. **Which `Idle` sessions show the waiting ring.** The Main board shows a finished-3-minutes-ago Codex session with the green ring and a done-14-minutes-ago one and a shell with the grey dot; today both are `SessionStatus::Idle`.
   - (a) Recommended: unseen turns. An agent session going `Working → Idle` shows the waiting ring until this client focuses it, then the idle dot; plain shells always show the dot. A client-side set, like the attention set. Worst case: two windows disagree, and a client restart shows every idle agent as seen.
   - (b) By mode only: every idle agent session shows the ring, every shell the dot. Worst case: an agent left overnight still reads as "waiting for you".
   - (c) By time: the ring for 10 minutes after the turn ends. Worst case: needs an idle-since time on `SessionSnapshot` (an additive protocol field and daemon change) in a restyle wave.
5. **Shapes for states the boards omit, and sizes.**
   - (a) Recommended: spawning = the hollow ring in `FAINT`, stopped = the idle dot at 55% opacity (as today), error = a filled `DANGER` dot with a white `×`; 12 px in leaves and pane headers, 9 px inside tab pills, 11 px in the footer (the boards' sizes). Worst case: a 12 px glyph in a 22 px one-line leaf crowds the row if question 6 picks (b).
   - (b) One 10 px size everywhere, no inner marks. Worst case: the asking diamond loses its `?` and differs from the waiting ring by outline alone.
6. **Leaf density.** The board's leaves have two lines (label; repo or branch) and a chip row when there are tab pills or tags; today's leaves are one 22 px line.
   - (a) Recommended: the board's layout, the second line always, the chip row only when it has chips. Worst case: about half as many sessions fit without scrolling.
   - (b) One 26 px line in Petal's colours, the branch in the tooltip. Worst case: the sidebar no longer matches the approved board.
   - (c) A Compact / Comfortable setting. Worst case: two layouts to spec and hand-test in every later wave.
7. **Terminal colours and the ground.**
   - (a) Recommended: the built-in terminal ground becomes #0C0B0E and the ANSI palette stays as ported (the contrast pass re-runs against the new ground); a user's or a program's (OSC 11) background still wins; the chrome stays graphite whatever the pane's ground; the "Graphite" background preset (#111318) is renamed "Slate" so it is not confused with the default. Worst case: a pane on the Paper preset sits as a bright hole in dark chrome (as today), and `theme.rs` stops matching the Tauri app's pinned values.
   - (b) Also retune the ANSI hues to Petal's (blue #6CA6FF, green #4FC89D, amber #F6BC4E, red #F26D6D). Worst case: every program's colours shift, and the syntax highlighting (lifted from the ANSI palette) shifts with them.
   - (c) Keep #08090b. Worst case: panes a shade darker and cooler than the boards.
8. **Rounded pane cards.** GPUI clips children to rectangles, so the terminal's painted background squares a card's bottom corners.
   - (a) Recommended: 8 px radius on the frame and header; the grid inset by the 1 px border, accepting square inner corners. Worst case: a small corner nick at high zoom.
   - (b) Square cards with gutters. Worst case: panes read harder-edged than the board.
9. **Board details the client could show today but does not.** The footer's "2 need you · 3 working · 1 waiting" counts (from today's statuses) and the `Ctrl N` hint on the Session button.
   - (a) Recommended: include them in PT.5 and PT.6, since the data exists. Worst case: a restyle item grows by two small features to review.
   - (b) Leave them to Wave 7. Worst case: the running client and the board differ at the hand-test, and someone has to remember why.
