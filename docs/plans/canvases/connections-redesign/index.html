Connections view: three layouts

RT-541 · Redesign the Connections view: grouped hosts, one row shape, add flows in place
"The Connections UI is kind of a mess, thrown together, with no sense of layout or organization or functionality."
Every lane keeps every function the picker has today: switch to This PC, a saved tailnet host, a saved SSH host or a discovered tailnet peer (a switch saves the host and sets last_target); Forget a saved host; add a tailnet host by name and port; add an SSH host with an optional remote command, with Test connection and its result; mark the current target; show Not paired; the scan's wait and error line; a typed host's refusal; Esc steps back, then closes. Sample data matches the current shots: current = This PC, saved box.tail1234.ts.net (tailnet, no device token) and me@buildbox (SSH), discovered laptop.tail1234.ts.net.
Per-host state the client knows (connection_picker.rs, connection_picker_view.rs, connection.rs, sidebar.rs)
Has nowCurrent target (row.target == conn.target()) and, for the current target only, its live connection::State: Connecting, Open, Closed / Error with a reason, AuthFailed, NotApproved (needs pairing). Not paired: a saved tailnet host with no device token, read once when the picker opens. Kind (tailnet / SSH), port, remote command. Scan pending ("Looking for your devices…") or failed (TailnetError text). Test connection: Idle, Testing, Passed (Connected: <short>), Failed (ssh's text). Typed-host refusal.
Cheap to addSessions last time: host_session_counts is already in native-ui.json per host (ssh:<host> for SSH). Online / offline for a saved tailnet host: the same tailscale status scan already lists it, the picker just filters offline peers out.
Not knownWhether a non-current host's daemon is up; whether an SSH host is reachable without running Test; a "last seen" time (nothing records one). No lane draws these.
A

Grouped list

Three sections in one 440 px modal, every host in one two-line row shape; click a row to switch. One Add host button opens an inline form with a Tailnet | SSH switch.

Worst case: with the add form open the modal is about 600 px tall with just these four rows, the whole 601 px window, so from the first extra host the list scrolls while adding (with 15 hosts, about 6 rows show, about 2 while adding). Forget shows only on hover or keyboard focus.

B

Two-pane

Settings' layout: a 200 px list of targets grouped as in A on the left, the selected host's detail and actions on the right. + New host is the list's last item and fills the right pane with the form.

Worst case: every switch costs a second action (select, then Connect, or a double-click / Enter); the modal grows to 600 px wide, and long MagicDNS names get cut to their machine name in the 200 px list.
