Pairing a phone: how the PC approves it

Settled already (owner rulings in remote-access.md, TS.3b): a phone on the owner's tailnet, logged in as the host's own Tailscale user, gets its device token only after it presents a one-time approval the host PC shows: a QR code, or the short pairing code beside it, both short-lived and single-use, started from the desktop app on that PC. Open here: who starts it and where the PC shows it. Every lane scans or types inside the installed Home Screen app, never the iPhone's Camera app, which would open the address in Safari instead. Content is a placeholder; codes and names are made up.

A. The PC starts it: QR in Settings, code beside it (collie's way)

At the PC, Settings → Remote access → Pair a phone shows a QR code and a 6-digit code for two minutes. The unpaired phone app opens straight on a scanner with the code boxes under it. Scanning, or typing the code, is the approval; the PC asks nothing more.

Worst case: you must be at the PC and think to open Settings first; a phone that opens unpaired while you are away (Safari cleared its storage) can do nothing until you are back at the desk.

B. The phone asks: a toast on the PC, then the code in a dialog

The unpaired phone sends a request by itself and waits. The PC raises a Windows toast (and the app's own banner) naming the phone and its Tailscale login. Approve opens a dialog in the app with the QR code and the 6-digit code for that one request; the waiting phone switches to its scanner by itself. Deny ends the request and tells the phone.

Worst case: toasts are skipped or missed (Focus Assist, away from the desk, the app minimised), and the phone waits on a screen it cannot act on; Approve still needs the scan, so it is two acts on two devices.

C. The phone asks: a waiting row in Settings, code first

The unpaired phone sends a request and shows the code boxes at once. On the PC nothing pops up: the Settings gear and the Remote access tab carry a count, and the page lists Waiting devices above the paired ones. Approve on the row opens a large 6-digit code with a small QR beside it; you type the digits on the phone (number pad), or scan.

Worst case: silent: if you do not know to look in Settings, the phone waits until the request lapses; a second unknown request in the list (another device on your account) looks just like yours apart from its name.

Borrowed from herdr's collie: lane A is collie's pairing as it ships: the host shows a QR code and the code it carries, the phone's form takes the code (filled in by the scan) and the token is stored once, with refusals that each say what to do next ("expired", "no pending", "bad code") and a paired-device list with a two-tap revoke (web/src/components/paired-devices.tsx, web/src/lib/pairing.ts, docs/install.md "Put it on your phone"). Collie mints the code from a terminal verb (collie pair); here the desktop app's Settings does. B and C, where the phone asks first, are not in collie.

Shared by every lane: the phone's own name comes from tailscale whois, never typed; a refused phone keeps no token; the paired screen asks for notifications on the tap iOS requires. Annotate anything: the code's length and lifetime, the words on the toast, where a Block lives.
