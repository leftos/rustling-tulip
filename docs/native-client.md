# Native client

The desktop client is `apps/native` (binary `rustling-tulip-native`): GPUI (Zed's UI framework) with `alacritty_terminal` for the terminal grid. It replaced the Tauri/WebView2 app, which lives on the `tauri` maintenance branch (tag `tauri-last`). The daemon, tracer and `crates/protocol` are shared and unchanged by the client. This doc records the decisions a change to the client needs to know; what each feature must do is in the [parity checklist](./plans/native-client-parity.md), and open work is in [plans/MAIN.md](./plans/MAIN.md). How the pieces fit together: [architecture.md](./architecture.md).

## Stack

- **GPUI 0.2.2 + `alacritty_terminal` 0.26.** The client moved off the web stack; GPUI draws natively and `alacritty_terminal` supplies a mature VT parser and grid. Iced is the fallback if GPUI's API churn becomes a problem.
- The native client can run side by side with the Tauri app against one daemon, since the daemon accepts several clients.
- **Crate rules.** `apps/native` is a main-workspace member under the workspace lints, prek clippy, `cargo test` and `cargo deny check`. `main.rs` is a thin binary over the library `rustling_tulip_native`, so specs link the library.
- **Testable core, thin view.** State a feature adds (sidebar tree, split tree, tab list, key mapping, span building, forms, dialogs' focus rings) lives in plain-Rust modules with unit tests; the GPUI `*_view.rs` renders it and forwards events. Every feature mounts into `RootView` (`lib.rs`), the hotspot concurrent items rebase over.
- **Clipboard** goes through GPUI's own API (no `arboard`).

## Daemon connection and protocol

- The client ensures the daemon through `crates/daemon-client` (`ensure_running`, passing `NATIVE_PROTOCOL_VERSIONS` from `net.rs`). A running daemon is reused when its supported versions intersect the client's, even from another build, so the client never fights another client over a stale binary; a daemon sharing none is retired through `/shutdown` and replaced, and its tracer sessions reattach.
- daemon.json carries `supported_versions` (`#[serde(default)]`; an older file reads as its scalar `protocol_version`).
- The native client speaks only the current protocol version (23). The daemon's `supported` keeps 22 for the installed Tauri app, and `main` keeps 22 decodable by discipline, proved by `cargo test -p protocol v22_compat`; there is no TypeScript mirror on `main`.
- **Client identity**: the native client keeps its own id file, `client-id-native`, so its tab layout stays separate from the Tauri app's (`client-id`).
- **Reconnect**: backoff 0.5 s → 10 s, a standby-resume watchdog, a connecting overlay with "Restart daemon", and a footer pill with a troubleshooting flyout. After a user-chosen shutdown the client never reconnects or respawns the daemon.
- **Request ids**: a client that must match a reply to its request sets the optional `request_id` (spawn, duplicate, scrollback, appearance, git reads, spawn previews, checkout prompts); the daemon echoes it only to the requester (CLAUDE.md, "Wire-protocol gotchas"). Adding one is additive; a reply without one (an older daemon) falls back to matching by content.
- Unknown daemon message types are logged with their tag and skipped; a frame that fails to decode is logged as an error.
- The client logs to `logs/native.log`, rotated on each launch.

## Persistence

Machine-local UI state lives in native-ui.json in the config dir (`UiState` in `sidebar.rs`; the field list is in CLAUDE.md, "Where things live on disk"). Tab layouts, session appearance overrides and host settings such as keep-awake and the worktrees root live on the daemon, so every client sees them. Saves are debounced (layout and tab font sizes 500 ms) and flushed on quit.

Settings → Worktrees edits the daemon's worktrees-root override, and shows `Saved` only once the daemon has echoed the last save. Manage worktrees (opened from that tab) lists the root's groups titled by their `.rt-group` name, deletes one group or every stale one, and "Launch session here" opens the spawn dialog with the target locked and that worktree pinned (the spawn form's `Lock`, which a duplicate prefill reuses). Folder pickers go through `RootDeps.pick_folder`, so specs inject a fake: GPUI's test platform cannot prompt.

## Terminal

- **Scrollback-first attach**: `LoadScrollback` with live output buffered meanwhile; an 8 s request timeout with retries after 2 s and 4 s, each with its own `request_id`, and a reply to an older id dropped. When the daemon restarts the forwarder (`forwarder_restarted: true`) the held-back output is discarded, since it is already in the history. The logical scrollback cap is 5000 lines.
- **Size and replies**: only one pane per session (its size driver) answers terminal queries, so a session shown in two panes gets each reply once. A query that ends the loaded history is answered unless live output follows it, which keeps a fresh ConPTY shell from sitting blank.
- **Copy and paste**: Ctrl+C copies with a selection, else sends ^C; Ctrl+Shift+C copies; copy on select is a saved setting (default on); paste on Ctrl+V and Ctrl+Shift+V, bracketed when the child asks. Shift+drag selects even under mouse reporting. OSC 52 `c` stores reach the system clipboard; reads are answered empty and stores in replayed history are dropped.
- **Keys and text input**: Shift+Enter sends `\` + CR for Claude and shells, `\n` for Codex and Cursor. GPUI gives Space no `key_char`, so `keys.rs` maps Space and Shift+Space itself; Alt+Space stays unmapped so Windows opens the system menu. Text arrives through an `EntityInputHandler` on the pane, so dead keys, AltGr and IME composition work: a composition is drawn underlined at the cursor even when the program hides it, and dropped on blur or stop; a dead key is not reported to GPUI as a composition, because GPUI would then hide Enter, Backspace, Esc and arrows from the pane. Ctrl+Alt with a non-alphanumeric character types it (AltGr on layouts GPUI doesn't know); Ctrl+Alt+letter or digit sends ESC+char.
- **Links**: `links.rs` ports the Tauri detector (URLs, absolute, UNC and relative paths with `:line:col`, stitched across soft and hard wraps and TUI borders within ±64 rows). Links underline only while Ctrl is held; Ctrl+click wins over mouse reporting. A path with `:line` opens in VS Code with `-g`, otherwise in the OS default handler. A path Windows flags as dangerous, or with a script or executable extension, asks "Run <name>?" first. A UNC path opens only for a host behind a mapped drive or listed in `unc_hosts` in native-ui.json, which the client reads on each click and never writes.
- **Shell integration**: OSC 133 and 633 marks drive per-command gutter dots (ok / fail / unknown) anchored to absolute rows through scroll, reflow and trim, with a menu to copy the command, the output or both, and to re-run (typed without Enter).
- **Theme and fonts**: every UI colour is a token in `palette.rs` (the Petal values, with contrast floors pinned by its tests). The terminal uses a fixed palette with ANSI colours contrast-adjusted against the background (`theme.rs`), on a built-in ground of #0C0B0E; the built-in session accent is Coral #F07A62, with six accent presets (Coral, Rose, Ochre, Periwinkle, Sky, Lilac); a program's OSC 11 background and OSC 12 caret colour win. The interface draws in Schibsted Grotesk (`fonts::UI_FAMILY`, set on the root view and the tooltip view; the terminal font picker never lists it). Geist Mono, Fira Code, JetBrains Mono and Cascadia Code are bundled for terminals, and Schibsted Grotesk at 400 to 700 for the interface (OFL, `assets/fonts/`); a family resolves against the installed list, falling back to Geist Mono, Cascadia Mono, Consolas, then Courier New.
- **Status glyphs**: a session's status draws as a shape as well as a colour (`status_glyph.rs`, tinted SVG layers in `assets/icons/status-*.svg`) in sidebar leaves, pane headers, Needs You rows, the tab bar's busy pill and the footer: a spinning arc while working, an amber diamond with `?` while asking, a faint hollow ring while spawning, a small dot when idle or stopped (dimmed), a red dot with `×` on error. An agent session (never a plain shell) whose turn ends (working to idle) while this client is not showing it focused is an **unseen turn** and shows a green hollow ring until its leaf is clicked or a focused pane shows it; any other status clears it. The unseen set is per window and not saved.
- **Petal chrome**: the look follows the user's Petal canvas, https://claude.ai/artifact/B5hxrVTyyR635CQecEpG2N, saved in `docs/plans/canvases/petal/` (a board per view; the Dashboard, Settings → Alerts, Conversation and phone boards are targets for the waves that build those features). The rail is 52 px on `SUNKEN` with 36 px tiles and a 2 px coral active bar; the tab bar 38 px on `SURFACE`, the active tab on `GROUND`; the footer 28 px on `SUNKEN`. Panes are cards with an 8 px radius, 6 px apart inside 6 px of padding (`PANE_GUTTER`; the sidebar and source-control handles keep `DIVIDER_WIDTH`), the terminal inset by the 1 px border with square inner corners. A pane header is one 36 px row (`RAISED` when focused, else `SURFACE`, a 3 px accent line on its left edge) holding the title, then the runtime, `repo:branch`, `+N` (further workspace members, listed with their worktree paths in its tooltip), headless and trusted chips, then 26 px buttons; when it runs short, the `repo:branch` chip truncates first, then the title, and the buttons never move. Dialogs are one card (`SURFACE`, 1 px `LINE_STRONG`, 14 px radius, a 16 px bold title, a raised footer) over a 66% scrim; menus, popovers and toasts sit on `CHIP` with a 10 px radius. Buttons are outlined, coral primary or danger-outlined (never filled) in `buttons.rs`'s sizes; disabled is 45% opacity, and keyboard focus is a 2 px `ACCENT` ring outside the control.
- **Truncating text with `…`**: gpui 0.2.2's text element reuses its cached shaping whenever a measure call carries no wrap width (`elements/text.rs`), and taffy's first measure of a flex child never carries a definite one, so `.truncate()` and nowrap + `text_ellipsis` clip mid-letter without an `…`, and wrap + `text_ellipsis` + `line_clamp(1)` can vanish outright in a stacked split, whose panes get a 0-width pass first. No view calls `.truncate()`; one-line text goes through `ellipsis.rs`, which has two shapes. `ellipsized(id, text, drawn)` is for a content-sized box that shrinks (the pane title, chips, sublines, the diff path): an invisible copy sizes the box to the whole text, and an absolutely positioned copy, laid out once at the box's final width, draws the `…`. `truncating(id, text)` (wrap on, `text_ellipsis`, `line_clamp(1)`) is for a `flex_1` or block row outside the pane grid (panel rows, heads, the footer), where the width is definite once flex settles; a site whose spec shows `truncating` drawing whole text in a narrow box uses the pair instead (the source-control picker went the other way: the pair drew whole there). Text that runs past its box by about a pixel now ends in `…` where the old clip hid the sliver. The source-control section head is two lines, repo then branch, each cut on its own. The in-process harness's fake text layout hides the cause, so specs read the drawn text: in debug builds each helper records its `TextLayout` under its id once a test calls `ellipsis::enable_probe()`, and `ellipsis::drawn_text(id)` returns it; `tests/ui/ui_ellipsis.rs` holds one spec per site.
- **Session menu** (a leaf, a pane header or a Needs You row, right-clicked): the state actions (Stop, Restart, Resume, …) first; then, behind a separator, `Duplicate ▸`, then `Move to ▸` when a pane shows the session or `Add to current tab` / `Add to new tab` when none does (one `Add to new tab` row when the placement would open a tab anyway, and neither when the session can't attach), then `Reveal worktree` for a session with its own worktree (it opens `members[0].worktree_path` itself); then, behind a separator, `Appearance…` and `Accent ▸`. A submenu swaps the rows for `‹ Back`, `New tab` and the grid tabs. Duplicate ▸ keeps the original, places the copy by pane target and brings that tab forward with the copy focused; a headless session's row is dimmed. Move to ▸ lists grid tabs not already showing the session, moves the right-clicked pane when opened from a pane header (else the first one showing it), and a move into a tab can be undone; Restart and Resume replace the original's panes and discard it. Shift on a Duplicate ▸ choice asks the daemon for the source's stored spawn config (`GetSpawnConfig`) and opens the spawn dialog on its reply, locked on the source's repo or workspace, prefilled after the Spawn defaults so the source's runtime, run mode, trusted flag, its own agent's options, model, env rows, base and worktree toggle win, with Open in set to the clicked target; the branch follows the daemon's duplicate rule (a worktree source gets a fresh suggestion, an in-place one keeps its branch), Advanced opens only for settings the source set, and a prefilled worktree toggle never saves the repo's worktree default. With no stored config the dialog opens on the source's repo with the defaults; a standalone source duplicates as a plain click does, since the dialog has no bare-folder target; a dialog that can't open when the reply arrives says why ("Duplicate failed"). The pending request is a slot keyed by session id (`session_actions.rs` `Prefills`). The model is `session_actions.rs`, the view `session_menu.rs`.
- **Session labels, chips and endings**: every label goes through `display_label`, with the full label in a tooltip; member chips get a second pane-header row only for sessions with members; the orphan banner names the session's own runtime; a worktree-less session that exits on its own is discarded, except headless sessions (kept so their stats can be read) and abandoned ones; the rename field keeps the native seed.
- **Leaf density**: sidebar leaves draw Comfortable (the default: a label line over a subline holding the branch, a workspace's `repo:branch · repo:branch`, or a shell's folder with home as `~`, the tab pills at its end or on a chip row below when they don't fit) or Compact (one 26 px line, the subline in the tooltip), set in Settings → General → Sidebar and saved as `general.leaf_density`. A leaf that needs you shows the asking glyph and the `!` badge, with no row wash. The footer counts sessions by glyph ("N need you", "N working", "N waiting", a zero count hidden; `footer.rs`), and a tab's busy pill reads "busy/total" with the working glyph, grey with no glyph at zero.
- **Appearance levels**: accent, shell background, font family, size and bold resolve session → repo/workspace → app → built-in, each shown with its source. Font size also has a per-tab override (Ctrl+Shift+= / −) above the session level (Ctrl+= / −); Ctrl+0 clears both.

## Source control and diffs

- Status, badge counts and diffs are keyed by (repo, worktree path), so worktree and main-tree counts never overwrite each other. Stashes are one list per repo.
- Git reads carry a `request_id`, so a failed read shows in its own section rather than as a toast; a write whose status refresh fails is answered with `GitWriteError`, so pending state always clears.
- **Diff engine**: `similar` computes line and inline word diffs on the client from the full texts `FileSnapshot` sends (Patience under a 2 s deadline; word spans skipped for a side over 1000 bytes). The daemon refuses a side that is binary or over 2 MiB, with the reason in `FileSnapshot.unavailable`.
- **Diff view**: a custom GPUI element, side-by-side only, rendering aligned rows in one `uniform_list` (synced scroll for free; hunk navigation is `scroll_to_item`; F7 / Shift+F7), with a 10 px overview ruler at its right edge marking each hunk (Ochre mixed, `WAITING` insert-only, `DIFF_DELETE` delete-only). Measured in release on 5k lines and 500 hunks: model build 2.6 ms, first drawn rows 58 ms, worst scroll draw 7.2 ms.
- **Diff tab header**: the file name first, whole, then its folder dimmed; the folder truncates with `…` before the name does, and the full path is in the tooltip. Below 900 px of header width the Whitespace and Highlight toggles show icons instead of labels; the change buttons are 24 px icon squares.
- **Syntax highlighting**: syntect 5.3 plus two-face 0.5 with fancy-regex (no C dependency), six token classes in Petal's diff colours (keywords Rose, functions Periwinkle, types and numbers Ochre, comments `SUBTLE`, strings `LILAC`; `TokenClass::color` in `syntax.rs`), independent of the terminal's ANSI palette and each at least 4.5:1 on the diff ground. It runs on the background executor after the uncoloured diff shows, stops past 20,000 lines, a line over 10,000 bytes or 2 s, and is a saved toggle. Cost measured in release: +1.29 MB on the exe (+5.6%), 570 ms for 5k lines of Rust. PowerShell is not coloured: two-face drops that grammar without onig.

## Notifications

OS toasts go through `tauri-winrt-notification` with no registered app id, so they show under a generic sender until the native installer exists. A stop this client sent does not notify this client. The daemon fans out `Attention { Error }` when a session enters Error, so every client agrees. The Notifications tab shows Windows' read-only toast state with a link to Windows' settings.

## Session recovery

A "Recover sessions" button sits on the activity rail above the Settings gear, with a badge counting unexpected ends (`TracerLost`) not yet recovered; an entry counts until it is recovered, from the dialog or the sidebar's Resume, or pruned after 7 days, and Dismiss does not clear it. The client asks for the history (`ListSessionHistory`) on every `Welcome` and keeps the daemon's broadcasts. The dialog (`recover.rs` model, `recover_view.rs` view) lists the last 7 days newest first: losses at an unknown time, then bursts of losses within 60 s of each other ("7 sessions lost at 11:29"), then the other ends collapsed behind "Show N other recent sessions". Unrecovered losses are pre-ticked; a row already recovered, or with no conversation to resume, is disabled with its reason. Each row offers its conversation candidates (the known id, else the newest) and, for plain-shell rows and rows with no spawn config, a "Recover as" choice limited to what the folder allows. A Codex or Cursor row has one fixed choice, its own agent, and says which way it goes: "Codex session, resumes its conversation", "…, fresh run: no conversation recorded" or "…, fresh run: its conversation is gone"; it offers no Claude transcripts, a row that would start a fresh run is not pre-ticked, and one with no spawn settings is disabled with "no spawn settings recorded". Sessions still in the sidebar's Abandoned group are listed too, and recovering one hands its panes to the new session (the daemon rebinds them), as the sidebar's Resume does; a per-session claim on the daemon stops the two paths recovering the same session twice. The rest of a run's recovered sessions are placed once every one of their snapshots has arrived, in one pass so no two share a pane, where a normal spawn would go; an answer that comes after the 120 s timeout or after the dialog closed is still placed. After a partial failure only the failed rows stay, re-ticked, with their messages.

## Needs You

A rail item after Sessions (an inbox tray) opens a panel listing every session waiting on the user, headed "NEEDS YOU · N"; its badge counts the rows (hidden at 0, `99+` above 99), and the rail never switches to it on its own. The list is plain Rust (`needs_you.rs`) over the sidebar model, drawn by `needs_you_view.rs`. A session is listed as **Asking** while its status is `AwaitingInput`, and as **Ended** while it is `Error` or `Stopped` and its leaf is still flagged; parked and abandoned sessions never are. Rows run longest wait first by the snapshot's `status_since` (the daemon's stamp of the last status change, kept across a reattach), rows with no stamp next, ended rows last, ties in sidebar order. A row shows the status glyph, the container name in its accent, the session's label and the time waited; line two reads "Waiting for input" (with the terminal title when it has one), "Error", "Exited with code N" or "Stopped". A click is a leaf click: it focuses or places the session's pane and clears the flag, so an Ended row leaves while an Asking row stays until the question is answered; right-click opens the session menu.

## Window

The window's restore rect, maximized flag and monitor are saved in native-ui.json and restored on that monitor (the primary when it is gone); fullscreen is not restored. The title reads `(M/N) Tab — rustling-tulip`, set 350 ms after its last change. Closing the window runs the quit flow (keep running, stop keeping worktrees, stop removing them with per-session branch fate, or abandon), waiting for `shutdown_ack`.

Closing a tab, closing a pane but keeping its session, and moving a pane to an existing tab each leave an entry on the undo shelf (bottom centre, 8 s, at most 3, newest on top). An entry holds a whole-tab snapshot of every tab it touched, and Undo sends `RestoreTabSnapshot` for a tab that still exists or `RestoreTab` at its old index for one that is gone; a tab this client has asked to remove (closing it, closing its last pane, moving its only pane out) counts as gone from the send until its removal arrives, so an Undo pressed inside that round trip still restores it, bringing back splits and ratios exactly; a pane whose session has since gone comes back empty. The shelf clears when the connection drops or a new `Welcome` arrives.

## Tests

Three tiers, all Rust tests:

- **UI specs** (`apps/native/tests/ui/`, one binary with a module per spec file): in-process, headless GPUI through the `test-support` feature (`VisualTestContext`), never touching the user's mouse or keyboard. `RootView::with_transport` takes the `NetCommand` / `NetEvent` channel pair, so specs script a fake daemon (`tests/support/mod.rs`), inject `DaemonMessage`s and assert on the `ClientMessage`s sent, grid text, selection and clipboard. `ui_dir` and the clock are injected, so specs never write the real native-ui.json. The test platform shapes text as fixed 0.6 em glyphs, so specs assert on cells, never on font pixels. Specs that rely on focus events call `window.activate_window()` first.
- **Live e2e** (`tests/e2e_live.rs`, `tests/e2e_recover.rs`, `.\rt.ps1 native-e2e`): the same harness against a real daemon whose config, binaries and worktrees dirs are all under `.tmp/`, set on the child with `Command::envs`, never process-wide. Specs create sessions through a clone of the client's `NetCommand` sender. A fake-claude spec with no `node` on PATH fails, never skips.
- **OS smoke** (`tests/smoke_window.rs`, `.\rt.ps1 native-smoke`): launches the real exe with `RUSTLING_TULIP_OFFSCREEN_WINDOW`, which opens it cloaked and never activated, so it never takes focus or covers the user's work. Before launch the spec writes the client's `client-id-native` and lays out its sessions for that id over its own socket, so the first-connect chooser never dims the probes. Input is posted to the HWND, keys 100 ms apart (closer spacing reordered letters under load). Pixels are read with `PrintWindow(PW_RENDERFULLCONTENT)` from the threaded show and probed for known UI colours and for a change in the pane after typing; the spec checks the window is still cloaked and not foreground after each capture.
- **Screenshots** (`examples/shot.rs`, `.\rt.ps1 native-shot [<view>] [-Out <path>]`): not a test tier but the way to look at a change. It opens the real window cloaked over `RootView::with_transport` and a fake daemon scripted in the example (four repos, a workspace, seven sessions in every status, a split tab, a diff tab), drives it to the view with the app's own keys (a posted click for the rail), waits for two equal captures (5 s at most), and writes `.tmp\shots\<view>.png` with the smoke tier's `PrintWindow` capture. No daemon starts and no config dir is read. The Working spinner animates on wall-clock time, so two shots differ inside that glyph and nowhere else.

The e2e and smoke tiers are `#[ignore]`d in `cargo test` and run only through their `rt.ps1` verbs. A probe or dev daemon never runs with default dirs, where its client attaches to the user's real sessions and resizes their PTYs: it sets all of `RUSTLING_TULIP_CONFIG_DIR`, `RUSTLING_TULIP_BINARIES_DIR` and `RUSTLING_TULIP_WORKTREES_DIR` to `.tmp/` dirs, as `native-e2e` does.
